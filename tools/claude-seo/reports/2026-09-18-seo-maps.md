## 0. Geocoding sanity check (do this before trusting any distance below)

Nominatim was queried three ways and gives three different answers, which matters because the
homepage's own JSON-LD `geo` block is the coordinate everything else in this report is measured
from:

| Query | Result | Distance from schema coord (-36.6173, 174.4829) |
|---|---|---|
| `12 Magnolia Lane, Kaukapakapa 0875` (exact address) | node at **-36.6274187, 174.5006538**, postcode returned **0843** | 1.94 km |
| `Kaukapakapa` (village centroid) | **-36.6151763, 174.4921211**, postcode **0843** | 0.86 km |
| Homepage JSON-LD `geo` (what's live now) | **-36.6173, 174.4829** | — (used as the center point for all radius math below) |
| Postcode `0875` boundary lookup | bounding box lat **-36.7295694 to -36.6395084** | the schema's -36.6173 lat is **north of this box** — outside it |

**What this means, plainly:** OSM/Nominatim does not have a clean, confident geocode for "12
Magnolia Lane" — its address-level node sits ~1.9 km from the coordinate the site publishes, and
the postcode Nominatim associates with the street number (0843) doesn't match the postcode used
on the website (0875). This is very common for rural NZ addresses with sparse OSM building data,
and Tier 0 **cannot tell you which coordinate is authoritative** — that requires either the actual
GBP pin (Tier 1/2 API) or a manual check in Google Maps / NZ Post PAF. Flagging it because a wrong
geo-coordinate on the LocalBusiness schema is a real ranking-adjacent issue (Google cross-checks
`geo` against the GBP pin), not because Tier 0 has evidence it's wrong. Recommend a manual
cross-check: open the live GBP listing in Google Maps, right-click the pin → "What's here?", and
compare the lat/lng to `-36.6173, 174.4829`.

All distances below use the **schema coordinate** (-36.6173, 174.4829) as "the salon," per the
brief, and Helensville town centre is Nominatim's town node: **-36.6799207, 174.4505396**.

## Limitations of this Tier 0 run — explicit

- **No geo-grid rank tracking.** Cannot show how "hairdresser Kaukapakapa/Helensville" ranks
  vary by location — requires DataForSEO Maps SERP API (Tier 1+). Not run, per instructions.
- **No live GBP field audit.** Everything in §(b) marked "Unknown" genuinely cannot be checked
  without either the DataForSEO My Business Info API or a manual login to the Google Business
  Profile dashboard. This report does not guess at those values.
- **No review intelligence** (velocity, 18-day-gap check, sentiment, fake-review screening) — needs
  a reviews API; only the 1 known review (5.0) was usable as a static fact.
- **Competitor list is an OSM floor, not a market census** — confirmed by the fact that the
  subject business itself isn't in OSM. Actual competitor count within 20 km, especially
  home-based/unlisted salons, is almost certainly higher than the 12 found.
- **Geocoding uncertainty is real, not cosmetic** (§0) — three different Nominatim queries gave
  three different coordinates/postcodes for the same address. Tier 0 flags this; it cannot
  resolve it.
- **Bing/Apple/Facebook/Yelp/Fresha presence was not live-verified** beyond a same-page string
  search on the homepage HTML (which found no links to any of them except Instagram). Actual
  listing existence/accuracy on those platforms requires manual login/claim-flow checks that a
  read-only, no-auth Tier-0 skill run cannot perform.
- **No cost was incurred** — Overpass API and Nominatim are free, no-signup services; no
  DataForSEO credits, no Google Maps API key, no Geoapify key were used (none are configured in
  this environment).
